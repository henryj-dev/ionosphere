## 0. 작업 원칙 (모든 배치 공통)

- **행동 결함은 먼저·작게·테스트와 함께, 구조는 그다음 초록 위에서.** 0단계가 결함 7건을

- **한 배치 = 워크트리 하나 = PR 하나.** `python3 scripts/claude-hooks/enter-worktree.py
  <이름>` → `ln -s ../../../node_modules node_modules` → 작업·커밋 → `npm run verify` 초록 →
  `git push -u origin <브랜치>` → PR → CI `gate` 초록 → 머지. **main 직접 push는 ruleset이
  거부한다**(`pull_request`·`required_status_checks`·`required_linear_history` — 2026-08-27 PR #12에서
  확인). CLAUDE.md의 `git push origin HEAD:main` 절차는 낡았다 — 8-A가 고친다.
- **배치 크기 상한 ±800줄.** 넘으면 쪼갠다. 리뷰할 수 없는 재구성은 재구성이 아니다.
- **이동 커밋과 수정 커밋을 분리한다.** 파일을 옮기거나 함수를 다른 파일로 뽑는 커밋은 **내용
  변경 없이** 먼저, 그 위에 수정 커밋. `git blame`이 끊기지 않고 리뷰어가 diff를 믿을 수 있다.
- **추출은 행동 불변.** 새 기능을 끼워 넣지 않는다. 행동이 바뀌어야 하는 곳은 §9 결정 항목을
  먼저 받는다.
- **규약은 린터로 못 박는다.** 0-B의 파일 크기 래칫이 계획 진행 중 어떤 파일도 더 커지지

  규칙을 같이 넣는다(기존 `checkDkimCryptoOwner`·`checkDomainLookupOwnership`이 그 형식).
- **회귀 테스트 없는 배치는 완료가 아니다.** 각 배치의 「완료 기준」이 완료 정의다.
- **커밋 제목 한국어** — `정리: …`(재구성) / `수정: …`(결함) / `docs: …`. 본문에 **왜**와

#### R-01 EXPUNGE가 Thread change_log를 절대 남기지 않는다

- **위치**: `packages/store/src/store.ts:1256-1262`, `:1338`, `:1349`
- **문제**: `targets`를 `{uid, messageId, sizeBytes}`로 매핑하며 SELECT가 가져온 `thread_id`를
  버린 뒤, 다음 줄에서 `(t as typeof t & { thread_id?: unknown }).thread_id`로 다시 읽는다.
  항상 `undefined` → `threadIds = []` → `state_thread`는 올라가는데 로그는 0건. 실증:
  append → setDeleted → expunge 후 `jmapChanges(…, "thread", before)`가 `state 1→3`에
  `updated: [], destroyed: []`.
- **수정**: `targets`에 `threadId: String(r.thread_id)` 유지, `threadIds`는 거기서 파생, 캐스트 삭제.
- **테스트**: `packages/store/test/jmap-changes.test.ts` — append → expunge → `Thread/changes`가
  해당 thread를 `updated` 또는 `destroyed`로 돌려준다. **멤버십 제거·destroy·COPY** 세 경로도
  같은 형식으로 추가(T-09가 요구했던 커버리지 — 1-A의 안전망이 된다).

#### R-02 `deferAll`의 bounce가 `NOTIFY=NEVER`를 무시한다

## 3. 1단계 — store 재편

store는 IMAP·JMAP·SMTP 어댑터 정리(2·4·5단계)가 모두 기대는 기반이다. **1-A → 1-B → 1-C →
1-D → 1-E 순서**. 1-A와 1-B는 같은 함수를 건드리므로 순차, 1-C/1-D는 병렬 가능.

### ☐ 1-A — 메시지 파괴 빌더 · 계정 상태 빌더 【P0 · T-09 정식 종결】

- **위치**: `packages/store/src/store.ts:441-455`(reap) · `:1303-1325`(expunge) ·
  `:1397-1411`(removeMembership) · `:1847-1861`(destroyMessage); 계정 UPDATE 변형 `:467`,
  `:1141-1151`, `:1222`, `:1348`, `:1407`, `:1417`, `:1753-1763`, `:1857`, `:1943`, `:2007`
- **문제**: 이번 diff는 `DELETE FROM message_text`/`search_index` 두 줄을 네 블록에 각각 넣어야
  했고, `removeMembershipAttempt`의 `isLast` 가지는 Thread 로그를 빠뜨렸다(R-01의 형제).
  `UPDATE accounts SET modseq = ?, state_email = ?[, state_mailbox = ?][, state_thread = ?][, used_bytes…]`가
  삼항으로 컬럼 부분집합을 고르며 ~12번 손으로 쓰였다. 다음에 파괴 시 지워야 할 테이블이 하나
  늘면(예: `thread_refs` GC) N−1곳에서 빠진다.
- **수정 방향**:
  1. `packages/store/src/message-destroy.ts` 신설(이동 커밋 아님 — 새 함수):
     - `destroyMessageStatements(ctx: { accountId; nextModseq; now }, dying: readonly { id; threadId; sizeBytes }[]): Statement[]`
       — `messages`·`message_mailbox`·`message_text`·`search_index`·`message_addresses`·
       `thread_refs` 삭제 + `ENTITY.Email destroyed` + `ENTITY.Thread updated` 로그. 내부에서
       `chunk()`로 파라미터 한도를 지킨다.
     - `detachMessageStatements(ctx, surviving: readonly { id; threadId; mailboxId; uid }[]): Statement[]`
       — 멤버십만 지우고 `expunged` 툼스톤 + `Email updated` + `Thread updated`.
     - `accountBumpStatement(accountId, nextModseq, touched: ReadonlySet<"email"|"mailbox"|"thread"|"submission"|"identity">, delta?: { bytes: number; count: number }): Statement`
       — `touched`에서 `state_*` 컬럼 목록을 **파생**한다. 손으로 고르는 삼항이 사라진다.

- **위치**: `packages/core/src/glob.ts:118-181`(정방향 DP), `:236-314`(역방향 DP + 탐욕 걷기),

- **문제**: 같은 4개 토큰 전이가 세 번 구현돼 있고, `regex.ts`의 Pike VM이 이미 같은 의미
  (leftmost-greedy 캡처, O(prog×input))를 낸다. glob은 자명한 regex AST다:
  literal→`char`, `?`→`group(any)`, `*`→`group(repeat(any))`, `%`→`group(repeat(class negate [구분자]))`,

- **수정 방향**:
  1. **동치 테스트 먼저**: 무작위 패턴(길이 ≤ 12, 알파벳 `a b / . * ? %`) × 입력 1만 쌍에
     대해 구 `compileGlob`/`globCaptures`와 신 구현의 (매치 여부, 캡처 배열) 동치 속성 테스트.
     이 테스트가 초록일 때만 구 코드를 지운다. 알려진 차이(강등 모드에서 `captures: []`)는
     신 구현이 "더 많이 맞는" 방향이므로 그 케이스만 제외 목록에.
  2. `regex.ts`에서 AST(`Node`)와 `compileAst(node, opts)` export.
  3. `compileGlob(pattern, syntax) = tokenize → Node → compileAst`, `globCaptures = execRegex`.
     `matchTokens`·역방향 표·탐욕 걷기·`MAX_CAPTURE_CELLS`·`GlobCaptureResult`(→ `RegexMatch`)·
     `globMatch`·`regexMatch` 삭제. `interpret.ts`의 `:matches`는 한 경로.
  4. `regex.ts`: `repeat` 동일 분기 삭제; `emitSplit(prog): { patchA(pc); patchB(pc) }`로 캐스트 제거.
- **완료 기준**: 동치 테스트 + `glob`·`glob-captures`·`regex`·`list-match` 테스트 초록;
  `glob.ts` ≈ 100줄(토크나이저 + 변환).
