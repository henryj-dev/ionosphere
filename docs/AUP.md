# 이용약관 — 수용 가능 사용 정책 (Acceptable Use Policy)

> 본 문서는 PLAN.md §8 "SaaS 신뢰·규정준수 모델" 통제 ④(AUP + abuse 대응)의 문서 축이다.
> 여기 서술된 강제 방식은 실제 코드가 구현한 것과 일치해야 한다 — 코드가 못 하는 것을
> 이 문서가 약속하지 않는다. (바운스율 자동 정지 로직: `packages/mta/src/abuse.ts`)

## 0. 핵심 원칙 — 내용 미열람, 구조적 통제

**운영자는 발송되는 메일의 내용을 열람하지 않는다.** 사용 정당성은 콘텐츠 검열이 아니라
아래와 같은 구조적 통제로 강제한다.

- 발신 도메인 소유권 검증 (DNS 확인 없이는 발송 불가)
- 계정별 레이트리밋 (분/시/일 발송 한도)
- 발송 후 관측 가능한 신호(바운스율)에 기반한 사후 자동 정지

즉, 운영자가 "무슨 메일을 보냈는지"를 봐서 판단하는 게 아니라 "누가, 얼마나, 어떤
결과로" 보냈는지를 봐서 판단한다. 콘텐츠를 열람해야만 알 수 있는 위반(스팸 문구,
피싱 여부 등)은 원칙상 운영자가 능동적으로 탐지하지 않으며, abuse 신고를 통해
사후적으로만 대응한다(§4 참조).

## 1. 금지 행위

본 서비스를 이용해 아래 행위를 하는 것을 금지한다.

- **스팸·대량 무단 메일**: 수신자의 동의 없는 대량 광고·홍보성 메일 발송
- **사칭·피싱**: 발신자·조직을 사칭하거나 신원·URL을 위장해 정보를 탈취하려는 메일
- **멀웨어**: 바이러스, 랜섬웨어 등 악성코드를 포함하거나 유포하는 메일
- **불법 콘텐츠**: 관련 법령을 위반하는 콘텐츠(아동 착취물, 불법 거래 알선 등)의 발송
- **타 도메인 사칭 발송**: 본인이 소유·검증하지 않은 도메인을 발신자 주소로 사용하는 행위

## 2. 발송 요건

계정이 외부 도메인으로 메일을 발송하려면 다음을 만족해야 한다.

- **도메인 소유권 검증 필수**: 발신 도메인은 DNS TXT 토큰 게시로 소유권을 증명하고
  `active` 상태여야 한다. 미검증 도메인의 발송은 게이트에서 거부된다
  (`packages/mta/src/enqueue.ts` — PLAN.md §8 통제 ②).
- **SPF/DKIM/DMARC 인증**: 발신 도메인은 SPF·DKIM 서명이 통과해야 하며, DMARC 정책을
  갖추는 것을 권장한다. DKIM 서명은 발송 파이프라인이 자동으로 부착한다.
- **수신거부 처리**: 수신자가 하드바운스·불만(complaint)·수신거부를 표명하면 해당
  주소는 suppression 목록에 등재되어 이후 발송이 자동 억제된다.

## 3. 레이트리밋 및 모니터링

- **계정별 발송 한도**: 분/시/일 단위 슬라이딩 윈도우로 수신자 수를 제한한다. 한도
  초과 시 해당 요청은 거부되며 클라이언트는 재시도해야 한다(PLAN.md §8 통제 ③).
- **바운스율 임계 → 자동 발송 정지**: 계정별로 최근 평가 창(기본 24시간) 동안의
  발송 결과를 집계해 바운스율을 계산한다. 최소 표본(기본 20건) 이상 발송한 계정의
  바운스율이 임계치(기본 10%)를 초과하면 해당 계정은 **자동으로 발송이 정지**된다
  (`checkAccountAbuse`/`suspendAccount`, `packages/mta/src/abuse.ts`; PLAN.md §8 통제 ④).
  표본이 부족한 계정은 정지 대상에서 제외한다 — 소량 발송 중 우연한 바운스로 오탐하지
  않기 위함이다.
- **신고율 기반 정지**: 수신자 신고(complaint/FBL) 데이터가 연동되는 시점부터 신고율도
  동일한 자동 정지 판단에 **포함된다**(2026-08-07 구현). 신고율 임계는 기본 0.3%로
  바운스율(10%)보다 한 자릿수 낮다 — 신고는 사람이 직접 "스팸이다"를 누른 것이라
  주소 오류(바운스)보다 강한 신호다. FBL 리포트(ARF, RFC 5965)를 소비해 집계한다.
  ⚠ `not-spam` 리포트는 **세지 않는다** — 그건 신고가 아니라 정정이다.

## 4. abuse 신고 처리 흐름

- 수신자 또는 제3자는 `abuse@` 주소로 위반 사례를 신고할 수 있다.
- 접수된 신고는 관련 계정·도메인의 발송 이력(메타데이터: 수신자 수, 바운스율, 발송
  빈도 등 — 본문 내용은 조회 대상이 아님)과 함께 검토한다.
- 조치 단계: **경고 → 발송 정지 → 서비스 해지**. 명백한 대량 피해(피싱, 멀웨어 유포
  등)가 확인되면 경고 단계를 생략하고 즉시 정지할 수 있다.
- 자동 바운스율 정지(§3)로 이미 정지된 계정에 대한 이의 제기는 abuse@ 로 접수한다.
